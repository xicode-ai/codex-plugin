# 业务知识文档行为评估

评估代理是否能从源码综合出有层次、可阅读的业务知识，不以出现多少关键字、生成多少文件或结构校验通过代替质量验收。

## 输入与隔离

用 evals/create_case.py 在新的临时目录生成合成输入。评估代理只能读取本 Skill 与指定原始材料，产物写独立输出目录；不给预期答案，也不读取以前的结果。不改输入、不调用外部服务、不安装工具、不导入知识库。不要拿真实系统源码发往外部模型服务做试验。

用户请求示例：

```text
请分析给定订单和仓库材料，生成产品经理、运营及业务问答可阅读的知识文档。
现有知识库只按段落或整句切分 Markdown，不解析元数据。
按系统、模块和主题组织，有业务小节与解释段落，正文不含代码、实现细节或源码引用。
没有数据库、前端和运行环境；证据与问题单独保留在 analysis/。
```

如果切换到新一版合成材料，应给状态提供明确的业务含义注释，避免要求代理凭程序标识猜测译名。对照分析要记录使用的 Skill/材料快照，限额或读取失败不算成功。

## 业务正确性（不给执行代理的判定项）

- 取消规则来自实际条件分支，不能把独立退款辅助处理并入取消流程。
- 自动处理开关关闭时不声称审核后自动分仓；计划未验收时不当作现状。
- 生产/消费的申请约定不一致时保留业务交接边界，不声称任务已创建或完整履约闭环。
- 仓库交接、承运商送达和客户签收的含义不能混淆。
- 不凭路由、接口声明或状态集合推定权限、租户隔离、校验执行、转换顺序、外部处理结果。
- 不补造页面、角色、真实使用量、退款时效或失败重试等未见规则。

## 正文质量

检查总览是否讲清定位与范围；模块是否讲职责、能力和上下游；主题是否说明场景、流程、规则、异常和结果。必须有二级小节和自然段解释，不能只有一级标题、全列表、全表格或同一长句反复套模板。

知识正文不能有程序片段、代码围栏、源码路径/类方法/接口、原始状态常量、技术实现、审计 ID、版本/哈希或引用括注，注释中也不放。检查 analysis/ 中的证据与文档私有映射仍然存在。抽取段落和关键规则句，看对象、条件、结果和重要限制是否保留；不要求每句重复完整系统名。

按 Skill 入口实际运行分析校验器和导出器；成功后再人工核对上述事项。脚本只拦截一部分结构和明显残留，不是业务正确性或深度的裁判。图源在 analysis/，正文可有文字/表格和可用的渲染图片。

## 真实产物回归

可以对用户已生成的 knowledge/ 做只读结构与残留检查，记录被拒绝文档数和问题类别；不要把不合格文件自动清洗覆盖后冒充完成新分析。真实产物中的业务事实需要重新追踪来源，不能仅凭现有文案判断正确。

新宿主按能力接入。宿主加载、工具调用、生成结果和 PG 实际检索分别记录；一次本地切分模拟不能证明知识库检索效果，也不能推广为所有宿主质量。
