## 验证范围与来源

本插件的业务知识文档、导出器和合成案例最初在源码业务分析插件的工作区中实现；用户明确要求独立新增插件后，相关能力移入本插件，原插件恢复。不能将原插件过去的清单或宿主验证直接当成本插件的加载验证。

知识库场景假定只按段落/整句切分 Markdown，不解析元数据或继承父级上下文。本插件生成 knowledge/ 业务正文与 analysis/ 证据/进度/维护清单，不连接 PG。

## 0.2.0：根据真实产物纠正为纯业务知识

日期：2026-11-03。用户提供 agy 生成的 yunshu_knowledgebase 文档，要求业务正文没有代码或源码引用，并具备正常 Markdown 小节与说明段落。

### 根因与实际观察

原 Skill 强制在每段写出来源、快照和证据 ID，导出器也要求正文出现这些标识；这把知识文档推向源码审计清单。检查用户目录中的 10 篇 knowledge 文档，均只有一级标题，带源码路径、类/方法和审计引用，缺少业务小节。只读检查没有修改用户产物，也没有把这些文案视为已证实的真实业务规则。

当前标准撤销公开引用要求，所有源码及审计信息仅留 analysis/；文档通过私有映射关联结论。正文必须有业务标题、小节、解释段落及自然语言流程/规则，不再按每句槽位重复代码版本与来源。增加防止“接口声明/枚举证明全部流程或外部结果”的调查要求，产品假设和未验收计划不作为现状知识答案。

### 自动回归与审查

- 全仓 93 项测试通过；其中知识插件 32 项在 Python 3.12 另行通过。
- Skill 格式、Claude 官方插件清单、Markdown 文件链接、严格 JSON 和版本一致性检查通过。原 source-business-prd 文件与原有市场条目保留。
- 新检查器只读检查用户提供的 10 篇知识文档，全部因缺少基础结构及明显代码/审计残留被拒绝；这验证闸门会拦截已知坏样例，不证明重写后的业务事实正确。
- 新增回归覆盖无公开引用的干净业务文档、非空私有结论映射、二级小节与解释段落、代码/接口/路径/类名/裸 ID/CRLF 元数据残留、原始图源、知识 ID 泄露以及保留正常系统业务名称。
- 独立只读代码审查发现明显残留与自定义私有 ID 的漏检，均先用测试复现后修复并复核。检查器仍是基础启发式，不是完整代码分类器、Markdown 引擎或业务质量评分器。
