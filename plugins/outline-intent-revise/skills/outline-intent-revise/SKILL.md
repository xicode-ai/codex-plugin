# 复核 Intent 评论并对齐修订

逐条核实已有评论，先交付可审阅的改进计划和回复草稿，得到该计划授权后才修改本地任务与 Outline。读取 [通用契约](references/workflow-contract.md) 的取证、复核对齐和写入恢复部分。脚本在本 Skill 的 `scripts/outline_intent.py`，先看 `--help`；脚本校验不能替代语义评审或真实用户授权。

## 授权前：取证、判断、完整草稿

1. `preflight` 检查当前 Outline URL/token，缺项请求安全提供。获取用户指定文档链接及完整正文/富文本/版本、全部分页评论和回复，保留评论ID/父子/锚点/状态。若只读无评论权限可复核但不能宣称可回复；不将断页当作没有意见。
2. 按 [intent 模板](assets/intent-template.md) 检查结构和内容，格式问题也纳入复核。检查当前窗口能否读取最新代码目录、对应本地 Trellis 任务、引用 PRD/规范；缺仓库或任务路径在对话请求补充，不按标题猜任务。产品 PRD 可选，纯技术改造注明不适用；不可访问的业务依据明确列缺口，不据此虚构结论。
3. 逐条判为成立/不成立/部分成立/证据不足，说明文档版本、原句、当前代码/PRD事实、规范或官方依据、当前系统影响与改造风险。不成立则给出解释草稿，不为迎合意见改造；证据不足先补证，不回复已修复。
4. 对成立项生成独立 staging 草稿和 diff，不修改被评审任务：列每条意见对应的 PRD需求/AC、design边界/数据流/契约、implement有序切片/公开测试入口/mock边界/验证，以及相关子任务/研究合同/JSONL。逐个比较全文并消除旧口径，不能只在文件末尾追加修订摘要。保持代码分析、稳定ID、既有批注和批准范围；复杂任务缺 design/implement 须补齐，轻量任务明确不适用依据。
5. 输出逐条结论、改进清单、所有具体文件/章节的完整替换稿或diff、拟同步在线正文和每条拟回复，并展示风险/回滚及仍未验证项。准备绑定源哈希、远端版本/评论快照、动作和回复ID的计划。**此处等待用户授权；此前不改本地Trellis任务，不改远端正文，不发回复或解决评论。** 已有本次具体计划的明确授权可继续，不能重复索要；其他任务/旧版本授权不自动覆盖新增范围。

## 授权后：对齐、同步、逐条回复

6. `prepare`/`apply` 或等价连接器执行已授权的同一计划，digest用于绑定字节，授权仍来自实际对话。先重新核对全部本地源哈希、远端正文版本与评论指纹；有新编辑时重整受影响内容和草稿，拟改正文/回复的实质内容改变或目标/动作范围扩大则交回审阅；仅无关来源变化且已确认批准内容完全不变，可更新快照沿用原授权，不重复请求同一许可。不能拿旧稿覆盖。
7. 先备份再按动作账本更新明确规划文件。PRD、design、implement、相关子任务和研究口径逐条检查一致；保留模板八个H2和非本次修改。需要本地批注时黄色标注对应原句，旁边展示原评论/复核/回复。更新相关JSONL引用和校验记录；不改产品代码、任务状态或启动实施。
8. 本地校验通过后同步计划内的 Outline 正文，保留标题/归属/未改区域及他人评论。富文本/行内锚点不能安全保留时按通用契约处理，不能以Markdown覆盖后“线程还在”冒充锚点完好。回读并对比语义/AC/版本，再向对应原评论ID发布已批准的回复，不把回复写成新根评论。
9. 每步回读确认内容/ID/父子关系，评论保持开放，除非用户明确授权解决。未实施的修订回复“已补充规划/待验证”，不写“业务已修复/生产已通过”。创建前固定并保存UUID/动作键；网络结果不明先按既定ID回读，服务不接受客户端ID时按完整快照新增项、parent/精确内容/作者/时窗唯一匹配核对，有歧义停止人工确认；部分成功明确阶段和待恢复项，不盲重试创建、自动回滚远端或宣布全部完成。

交付本地文件链接、远端文档/revision、逐条回复回执及各项验证状态。文档对齐、测试、实际端点、压测和部署分别报告；没有运行就写未运行。
