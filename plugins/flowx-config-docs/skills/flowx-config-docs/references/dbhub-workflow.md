# dbhub 查询工作流

## 1. 能力发现

调用具体工具前，读取当前会话实际可用的 dbhub MCP 工具描述。只选择能证明以下能力的工具：

- 目标数据源或数据库身份确认；
- Schema、表和字段发现；
- 只读 SQL 或等价条件查询；
- 查询结果和错误分类。

不要根据旧项目、旧会话或记忆中的工具名直接调用。当前会话没有对应能力时，状态为 `blocked`。

## 2. 目标确认

用户提供的数据库名或数据源标识必须先映射到唯一目标。确认结果只保留非敏感摘要，例如数据库名、Schema 名和数据源显示名。不要把用户名、连接地址、密码、Token 或完整连接串写入文档。

目标确认失败、目标不存在、目标不唯一或权限不足时，停止相关查询并记录查询受阻原因。

## 3. Schema-first

先读取 Schema、表名和字段名，再根据配置需求查询记录。候选识别依据包括：

| 配置类型 | 重点语义 |
|---|---|
| 数据字典 | 字典类型/编码、key、value、中文值、语言值 |
| 菜单权限 | 菜单名称、父级、类型、编码、路由、排序、授权标识、授权资源 |
| 国际化 | 一级 key、二级 key、中文值、语言代码、语言值 |

再结合用户业务关键词筛选记录。默认不执行整库记录导出。

## 4. 候选和结果分类

- 唯一候选：执行目标条件的只读查询。
- 多个候选：返回表名、字段摘要和匹配原因，等待用户选择；不猜测。
- Schema/候选表已确认且目标条件查询成功但返回零行：记录为 `empty`，对应章节输出空模板和精确文本 `> 未查询到匹配配置。`。
- 没有候选表或字段无法可靠识别：记录为 `unresolved`，对应章节保留空模板并写入无法识别配置表的说明，不使用 `未查询到匹配配置`。
- Schema、数据源或查询不可用：记录为 `blocked`，不得伪装为 `empty`，也不得生成看似成功的配置记录。
- 同一 key/语言出现互相冲突的值：保留冲突说明，不静默覆盖。

## 5. 证据边界

只把归一化后的配置字段、记录数量、非敏感匹配依据和状态写入 payload。原始响应、完整 SQL、参数值和凭据不进入文件。dbhub 本流程只读，不执行写入或清理。
