# 受控行为评估

评估对象是宿主代理使用 Skill 后的实际产物，不是文档中是否包含指定词语。脚本单元测试另见仓库 tests/test_source_business_prd.py。

## 可复现输入

```bash
python3 <plugin-root>/evals/create_case.py /tmp/source-business-prd-case-unique
```

输出是新目录中的两个合成仓库、旧产品计划及 request.md；不访问网络或数据库。已有目标目录会被拒绝，避免覆盖。用合成材料试分析不代表真实系统效果。

两次分析都只给原始源码和 request.md，不给下述预期答案：

1. baseline：独立新代理不读取本 Skill，产物仅写 baseline-output/。
2. forward：另一个独立新代理加载本 Skill，产物仅写 skill-output/；不读取 baseline 输出。
3. 主评估者核对源码与输出，运行结构校验；把原始执行限制和实际结果记录在 results.md，不把单样本表现推广为普遍准确率。

可用提示：

```text
请完成 <case-root>/request.md 的任务。只访问 orders/、warehouse/、legacy-product-notes.md 和 request.md；所有输出写 <指定输出目录>。
不改输入，不调用外部服务。报告实际产物与限制。
```

forward 额外指定使用 `<skill-dir>/SKILL.md`，允许读取其内部资源和运行校验脚本。不要额外提示具体预期错误，否则结果不是独立试验。

## 人工判定规则（不给执行代理）

- 取消只接受 NEW / APPROVED，REVIEW 明确拒绝；不把未出现的退款动作附加到取消流程。
- 审核设置 APPROVED，但当前文件常量关闭自动下发；不能推出自动分仓已启用。
- 生产者 v2/order_id 与消费者 v1/order_no 不匹配；交接不可标 matched，闭环保留缺口。
- DELIVERED 在回调内仅表示交仓，不等于承运商送达或客户签收；不虚构仓库主动调用回调的链路。
- 退款只在 orders/legacy.py 定义，给定文件未展示调用方；不能宣称已接入，也不能说文件为空。
- 业务动机区分文档意图与推断；未验收的旧计划不当作现状事实。
- 没有 DB/UI/运行环境时不生成虚假的查询、页面或生产使用结论。
- 文件、符号、行号和哈希对应实际内容；正文、图表与证据引用一致。状态初始创建未知时不画已证实初态。
- 生成检查点、实际覆盖和下一步；结构校验通过仍需人工核对语义。

## 后续验证矩阵

当前合成案例覆盖多仓库、事件冲突、配置关闭、孤立函数、文档冲突及无数据库降级。可继续增加：单仓库、双端匹配的 HTTP、缺失消费者、数据库零行/失败/截断、租户与一对多口径、源码变更后恢复。单元测试验证这些字段的结构约束，不能代替宿主行为评估。

真实系统试分析需要用户指定仓库、环境与输出范围；数据库查询和生产行为验证分别记录。对实际接入的每个宿主，记录名称/版本、指令加载方式、能力映射、工具调用及实际任务结果；宿主集合开放，不限于任何几个产品。使用相同案例与判定规则，不以同一份 Skill 格式支持推定全部宿主端到端通过。

接入未列名宿主时，检查是否能沿通用协议执行：有原生 Skill 机制时原生加载；无原生机制但可读指令/文件时显式加载入口；只有文件工具时降级代码检索；无 Python 时记录脚本校验未执行；缺少必要证据时保持草稿。不能因宿主未列名而直接拒绝，也不能因格式可加载而跳过能力检查。
