# dbhub MCP 工作流

## 能力发现和环境确认

先读取当前会话中的 dbhub 工具和参数 schema，匹配：

1. 数据源/环境解析。
2. schema、表和字段发现。
3. 只读查询。
4. 测试夹具准备。
5. API 后置校验。
6. 清理或回滚。

不要假设某一版本的 dbhub 工具名。缺少结构发现或结果校验能力时，相关用例只能为 `BLOCKED`。

## 只读优先

1. 用环境标识解析目标数据源。
2. 先读取表、字段、主键、状态字段和关联关系的安全摘要。
3. 查询数据分布、可复用测试夹具和唯一约束。
4. 将查询限制在必要的列、行数和业务范围内。
5. 不把明文凭据、个人敏感字段或完整业务记录复制到对话和报告。

如果无法确认表或字段含义，停止生成依赖该对象的断言，不用名称相似的表替代。

## 测试数据计划

优先复用现有、明确标记为测试用途的数据。必须新增时：

- 使用唯一的测试标识，例如带任务前缀和时间片的非敏感值；
- 记录逻辑 fixture ID，不记录凭据或完整业务数据；
- 明确 API 调用前状态快照、预期新增/修改范围和清理条件；
- 任何写入都需要逐条确认。

无法限制影响行、无法确定唯一键或无法安全清理时，标记 `BLOCKED`。

## 前后置校验

API 调用前查询必要的状态快照，调用后按用例断言查询：

- 记录是否创建、修改或删除；
- 状态是否按预期迁移；
- 关联记录、计数和唯一性是否符合预期；
- 重复调用是否保持幂等；
- 失败或拒绝是否没有产生意外写入。

查询结果以计数、状态、存在性和脱敏摘要呈现。避免返回完整行、完整 SQL、原始参数或未经处理的异常。

## 清理

清理策略只能使用测试计划中已经确认的范围：

- 无副作用场景：记录 `none`；
- 已确认且可定位的夹具：使用 `delete-fixture` 或已批准的回滚；
- 无法安全界定范围：记录 `manual` 或 `BLOCKED`，不要自行删除。

清理失败必须进入报告的环境影响和遗留风险部分。
