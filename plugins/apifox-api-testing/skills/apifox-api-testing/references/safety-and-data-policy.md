# 安全、数据和执行门禁

## 确认范围

以下动作必须逐条确认：

- API POST、PUT、PATCH、DELETE、提交、审核、取消、重试和状态迁移；
- dbhub INSERT、UPDATE、DELETE、DDL、回滚和清理；
- 任何无法证明为只读的动作。

确认内容包含用例 ID、目标 method/path 或数据对象类别、预计影响范围、测试数据标识、清理策略和不执行风险。一次确认只覆盖一个用例。

## 敏感信息

永不持久化或复述：

- Authorization、Token、Cookie、密码、Secret、数据库连接串；
- 预约码、验证码、个人身份字段和完整业务请求/响应；
- 带敏感参数的完整 SQL、异常堆栈或原始工具输出。

证据只保留脱敏后的状态、计数、字段存在性、逻辑条件和短摘要。

## 重试与失败

- 写操作不自动重试。
- 只读网络失败最多重试一次，并标记 retry。
- 超时、CLI 或 MCP schema 不匹配、权限不足或数据库不可达时标记 `ERROR` 或 `BLOCKED`，不要伪造业务失败。
- 用户拒绝副作用操作记为 `SKIPPED`，依赖其结果的场景记为 `BLOCKED`。

## 环境和清理

Apifox 与 dbhub 必须解析到同一个用户指定环境。环境映射不明确、写权限超出范围、清理条件无法定位或影响行不受控时，停止相关动作。

清理只能针对本次获准且带唯一测试标识的数据。清理失败进入报告的环境影响和遗留风险，不尝试扩大删除范围。
