# 笔记属性维护

使用文件开头的 YAML frontmatter 维护 Obsidian Properties。属性帮助检索、去重、导航和识别证据范围；不能把属性存在当作正文已核验。库内现有字段名称、取值、类型与用户当前指令优先，不强制所有库迁移到本文件的示例。

## 范围与覆盖

完整维护每轮检查可读范围的属性覆盖，在既有维护状态中保存已检查、已补齐、证据不足、冲突、只读跳过和待处理批次。没有变化且已合规的笔记不重写；本轮做不完时保留逐篇路径或可定位的批次进度，不宣称每份已完成。

| 笔记类别 | 维护方式 |
|---|---|
| 06-Wiki 的知识正文、知识导航 | 新建时加入属性；已有页面在可写范围内按批次补齐 |
| 03-外部资源的来源说明、收集记录 | 维护来源身份、日期依据、完整性和整理进度，沿用现有分工 |
| 新建的来源正文 | 仅当采集规则允许添加 frontmatter 且保留原始副本时写入；要求逐字保真的内容不添加属性 |
| 已有原文、同步器管理的来源镜像、附件、备份 | 不改原件；已有来源说明或去重索引承载属性。不要为每份原文机械新建一份重复说明 |
| 本轮新建阅读导读 | 加入笔记属性；正文与当天资料资格继续遵守导读规则 |
| 本自动化唯一运行状态记录 | 维护其自身类型与用途；状态不是知识证据，不把运行字段写进普通知识页 |
| 个人原稿、进行中其他笔记、成品、规则页、既有历史与既有导读 | 默认只读；仅记录属性缺口。用户明确授权的具体路径与字段可在该范围补齐，不扩展到凭据或其他禁止读取内容 |
| 凭据及禁止读取的材料 | 读取前排除，不扫描属性、摘要、正文或内容哈希 |

“全库覆盖”指可读范围逐篇核对并记录处置，不等于有权改写全部文件。补属性也是修改；不通过 `property:set` 绕开写入边界，也不改库规则或 `.obsidian/types.json` 来迁就新字段。

## 字段契约

先用允许读取的已有代表页和 `obsidian vault="<库名>" properties path="..." format=yaml` 了解本库约定；避免为一项含义新增中英两套字段。没有统一约定时使用下表。每份可写笔记至少维护可确定的 `title` 与 `type`；已存在等价标题/类型字段时直接沿用，不强制增加同义字段。其余字段有实际用途和证据才写，不为形式完整补空列表、空串、“未知”占位值或当前日期。

| 字段 | 类型与含义 | 何时维护 |
|---|---|---|
| `title` | 文本，笔记标题 | 优先沿用已有值，无值时从明确的一级标题取得；无一级标题时可用当前文件名，不因此改正文标题或文件名 |
| `type` | 文本，笔记类别 | 沿用本库分类；无约定时可用“知识笔记”“知识导航”“来源说明”“收集记录”“阅读导读”“运行状态”。已有“概念与设计分析”等更具体类别保留，不统一覆盖 |
| `tags` | 文本列表，检索标签 | 阅读内容后复用本库标签；只加有直接支持的主题，不按目录批量猜测，不追求每页固定数量 |
| `aliases` | 文本列表，实际使用的别名 | 正文、来源或本库已有别名支持时补入；不是自动生成一组近义词 |
| `domains` | 文本列表，所属知识领域 | 沿用已有领域目录和导航中的归属；跨领域须有内容依据，不为补属性新建领域 |
| `created` | 日期，本地笔记创建日 | 新笔记用本次运行的北京时间日期；旧笔记仅凭可信创建记录补齐。不能用当前日期、文件 mtime 或源发表时间替代 |
| `updated` | 日期，本地笔记正文实质修订日 | 有正文或知识判断的实际变更才更新；仅补属性、改标签、修格式或例行扫描不刷新 |
| `status` | 文本，本库既有内容/处理状态 | 只依据实际完成步骤与已确认状态维护；不自动把草稿改定稿、进行中改完成，属性齐备也不等于已整理 |
| `sources` | 文本列表，可定位的来源链接 | 知识笔记确有引用时维护；列表不代替正文结论旁的章节/段落证据，不能根据 Wiki 互链猜来源 |

来源说明或采集元数据还可沿用 `source_url`、`source_id`、`source_updated`、`published`、`collected`、`first_seen_at`、`content_complete`、`attachments_complete` 等字段：

- URL 和 ID 必须实际取得；不含 Token、Cookie 或临时签名下载 URL。保留采集器现有 `outline_id` 等身份字段，不擅自更名。
- 来源发表、来源修订、收藏、本地收集和首次发现是不同时间；沿用本库现有语义，必要时在来源说明解释。`created`、`updated` 只表示本地笔记，不能覆盖来源日期。
- 可靠收藏时间缺失时，不因为添加了属性就填写 `collected`；未知在来源说明正文标注。`first_seen_at` 使用实际发现记录的带时区 ISO 8601 时间，首次基线、历史回填与后续发现继续分开，不能据属性回填日期制造当天新增。
- `content_complete` 与 `attachments_complete` 为布尔值，只在确实核对后填写；元数据已取、正文已取、图片已下和图片已读分别判断。证据不足可省略，不能默认 true。
- `verified` 不作为每页必填项。核验某个事实不等于整页通过；优先在正文说明具体范围，不能仅因属性检查而统一刷新日期。

例：已有知识页仅补标题与实际标签，可保持原来的创建和正文更新时间：

```yaml
---
title: WMS 产品序列号管理
type: 概念与设计分析
created: 2026-10-12
updated: 2026-11-05
domains:
  - 后端技术
tags:
  - WMS
  - 序列号
aliases:
  - SN 管理
sources:
  - "[[03-外部资源/企业知识库/相关文档]]"
---
```

这是格式示例，不能照搬日期、领域、标签或虚构的链接。没有实际来源时省略 `sources`，已有同类字段及原有列表项保留。

## 增量写入与验证

1. 确定本页可读、可写和类别；读取现有 frontmatter、正文及必要的可定位来源，列出具体字段补丁及依据。只读取到元数据不能推断正文主题标签或摘要。
2. YAML 已有语法错误、重复键、同义字段冲突、同字段类型不一致或自定义结构时，不重建整段 YAML，不自动纠正全库类型；保存问题供确认。保留未知自定义字段、嵌套结构、注释、列表顺序与用户值；工具不能可靠保留时跳过，禁止用简化解析器丢弃字段后重写。
3. 旧页修改前保存可恢复备份与读取哈希，写入前重读核对。只补目标字段，已有列表在保留原顺序前提下按本库约定去重合并；不排序整个 frontmatter。新页确认不存在再创建。
4. 官方 CLI 提供 `properties`、`property:read`、`property:set`，先用 `obsidian help property:set` 核实当前参数。可用 `obsidian vault="<库名>" property:set path="..." name="title" value="..." type=text` 更新单字段；这仍会改文件，必须先备份与核对。列表取值/转义按当前 CLI 帮助核实，不能猜分隔符。也可精确编辑 YAML；不把不可信值拼成 shell 代码。
5. 校验 frontmatter 处于文件开头、YAML 可解析、无重复键。`title`/`type` 为文本，`tags`/`aliases`/`domains`/`sources` 按本库契约为文本列表，布尔值不写成字符串；与已确认的旧契约不同则报告冲突，不能静默转换。内部链接属性的字符串需要引号，列表链接目标应实际存在。
6. 写后用官方 CLI 回读属性，核对值、类型、列表和相关链接。仅补属性时比较正文，必须保持不变；校验所有非目标字段与自定义值未丢失，备份可恢复。若需要 Obsidian 界面验证而未执行，明确标记未运行。
7. 缺少证据的字段省略并在既有状态中说明；仅属性补齐不算当天新资料或新理解，不进入阅读导读。不为每次扫描写 `last_checked`、修改 `updated` 或生成新报告来制造活跃；无变化则跳过写入。
